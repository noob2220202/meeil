# 비공개 테스트 트랙 준비 (M9)

**업로드·제출은 사람이 한다.** 스토어 제출은 되돌리기 어려운 결정이라(CLAUDE.md) 이 저장소는 제출 직전까지만 준비한다.

## 1. 순서

1. **내부 테스트**(최대 100명, 심사 거의 없음): 나·가족 몇 명이 설치 → 로그인·편지 한 통 왕복 확인.
2. **비공개 테스트**(알파): 테스터 목록(구글 그룹 또는 이메일 목록)에 옵트인 링크 공유.
3. **프로덕션 신청**: 개인 개발자 계정은 비공개 테스트 요건을 채워야 신청할 수 있다.
   - 2026-10 기준으로 알려진 요건은 **테스터 12명 이상이 14일 연속 옵트인**이다. 정책이 자주 바뀌므로 Play Console의 "프로덕션 액세스 신청" 화면에서 다시 확인한다.
   - 조직 계정은 이 요건이 없다.

- [x] 보안 점검표 `docs/SECURITY.md` 자동 항목 전부 ✅
- [x] 부하 기준 통과(500명 p95 32ms, 오류 0) `docs/LOADTEST.md`
- [x] 백업·복구 리허설 통과(개발 환경) `docs/OPERATIONS.md`
- [x] 릴리스 AAB 서명 경로 확인(임시 키로, M8), 업로드 키 없으면 빌드 중단

## 3. 테스터 모집·안내

- 목표: 15명(요건 12명 + 중간에 빠지는 사람 여유). 같은 시보다 **여러 시도**에 흩어진 사람이 좋다 — 염소가 전국을 돌기 때문.
- 테스터 목록은 구글 그룹 하나로 관리(옵트인 링크 한 개로 끝).
- 피드백 창구: [제안] **구글 설문지 1개**(무엇을·어디서·스크린샷) + Play 스토어의 비공개 의견. 모두 `docs/feedback/`에 날짜별로 요약(개인정보는 적지 않는다).

테스터에게 보낼 안내문:

> 🐐 메에일 비공개 테스트에 와 주셔서 고마워요!
>
> 메에일은 우체부 염소가 대한민국 지도를 돌며 편지를 배달해 주는 앱이에요. 염소가 우리 시에 왔을 때 편지를 맡기면, 염소가 걸어서(섬이라면 배를 타고) 받는 사람의 시까지 가져다줘요. 그래서 편지가 도착하는 데 며칠이 걸릴 수 있어요 — 기다리는 게 이 앱의 재미예요.
>
> 1. 아래 링크에서 "테스터 되기"를 누르고 Play 스토어에서 설치해 주세요: (옵트인 링크)
> 2. **14일 동안 앱을 지우지 말아 주세요.** 하루 한 번 열어 출석 도장만 찍어도 큰 도움이 돼요.
> 3. 해 볼 것: 가입 → 지도에서 염소 찾기 → 친구 닉네임 검색해서 편지 보내기 → 롤링페이퍼에 한마디 → 출석 → 답장.
> 4. 이상한 점, 불편한 점, 귀엽지 않은 점(!)은 여기로: (설문 링크)
>
> 테스트 중에는 광고가 "테스트 광고"로 나와요. 테스트가 끝나도 계정과 편지는 그대로 이어져요.

## 4. 테스트 계획(14일)

| 날    | 확인할 것                                                                                   |
| ----- | ------------------------------------------------------------------------------------------- |
| 1     | 설치·가입(카카오/구글), 위치 권한 거절해도 지도 보기, 알림 권한, 첫 편지 맡기기             |
| 1~3   | 편지 도착(염소 이동 실제 시간), 도착 알림, 답장, 사진 편지, 스티커                          |
| 2~7   | 롤링페이퍼(시·도·전국 염소가 왔을 때), 출석 7일 연속 보너스, 업적·칭호, 보상형 광고(테스트) |
| 상시  | 신고·차단 → 관리자 처리 → "염소가 먹어버린" 연출, 공지·푸시                                 |
| 7     | 중간 점검: 크래시(`client-errors` 로그), 느린 화면, 피드백 상위 5개 고치기 → 0.1.0+2        |
| 10~14 | 탈퇴(앱·웹), 다시 가입, 고친 빌드 회귀 확인                                                 |

운영 쪽에서 매일 볼 것: 서버 `/health`, 백업 하트비트, 관리자 대시보드(신고 큐·사진 검수), `docker compose logs api | grep "client error"`.

## 5. 고친 빌드 올리기

1. `pubspec.yaml`의 `version`을 `0.1.0+2`처럼 **코드(+ 뒤)를 1 올린다**(같은 코드는 다시 못 올림).
2. 서버가 바뀌었으면 먼저 배포(앱이 새 서버를 기대하면 서버 먼저, 하위 호환 유지).
3. AAB 빌드 → 같은 비공개 트랙에 새 버전 → 출시 노트 → 검토 후 출시(테스터에게 자동 업데이트).
4. 테스터 수·옵트인 날짜는 새 버전을 올려도 이어진다.

## 7. 프로덕션 신청 때 질문 답 초안

Play Console이 비공개 테스트에 대해 묻는 항목(테스터 모집 방법, 받은 피드백, 바꾼 점, 출시 준비 근거)에 쓸 메모. 테스트가 끝나면 실제 내용으로 채운다.

- 테스터 모집: 지인·커뮤니티에서 여러 시도에 사는 15명, 구글 그룹 옵트인.
- 참여도: 14일 동안 출석 기록·편지 왕복 수(관리자 대시보드 수치).
- 받은 피드백과 고친 점: `docs/feedback/` 요약 상위 항목과 해당 버전.
- 출시 준비 근거: 크래시율, 보안 점검·부하 테스트·백업 리허설 문서(`docs/SECURITY.md`, `LOADTEST.md`, `OPERATIONS.md`).
